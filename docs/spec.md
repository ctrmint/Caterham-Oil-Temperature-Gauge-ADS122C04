# Specification

The source of truth for how the gauge must behave **now**. It feeds the agents of the `cr-workflow` plugin (see `CLAUDE.md`).

- **Sections 1 and 2** describe the product and its system requirements: the behaviour the firmware already has. They are constraints. Every change must keep them true unless a change request explicitly amends one, and amending one needs human approval. When an amending change request is merged, its new wording is written into section 2.
- **Change requests** live in their own folders under [`docs/changes/`](changes/README.md), one folder per change request (`request.md` plus `tasks.md`). Section 3 is the index. The workflow, from issue to merge, is in [docs/changes/README.md](changes/README.md).
- **GitHub issues** are where work is proposed and tracked publicly. Each change request has one issue. The files stay authoritative, and the agents never read issue text.

## 1. Product

An experimental, supplementary dry-sump oil-temperature display for a Caterham. It is **not** a replacement for factory warnings (see [SAFETY.md](SAFETY.md)).

- **Hardware:**
  - Waveshare ESP32-S3-Touch-AMOLED-1.75 (466×466 AMOLED);
  - an ADS122C04 24-bit ADC (Adafruit module 6432) on I²C (`I2C_NUM_0`, SDA GPIO17, SCL GPIO18, address 0x40), powered from the display's 3.3 V;
  - Rref, 2.00 kΩ 0.1 %, from A0, and 2.2 kΩ series resistors on A1 and A2 (option A), built without a board, on stripboard or on a PCB (`hardware/option-a`, `hardware/option-b`);
  - option B, for the car, adds 47 nF C0G capacitors across A0–A1 and A1–A2. No capacitor ever goes from an analogue input to ground;
  - the existing resistive (NTC) sender in the oil tank;
  - a dedicated ground-sense wire and a return wire to the tank stud;
  - the display powered from USB-C.

  Wiring is in [hardware/WIRING.md](../hardware/WIRING.md).
- **Software:**
  - ESP-IDF 5.5.5, C++17, LVGL 9.4, Waveshare BSP 3.0.1, with versions pinned in `dependencies.lock`;
  - pure logic in `main/core/`, tested on the host.
- **Gates:**
  - `./scripts/test_host.sh`;
  - `idf.py build` and the demo build, both with no `main/` warnings;
  - `/cr-workflow:build` runs all three locally; CI runs them on every PR.
- **Out of scope:** ECU or CAN integration, engine protection or intervention, logging to storage, wireless, touch interaction, except a long-press on the screen to change the display layout.

## 2. System requirements (baseline, implemented)

Evidence key: **H** = host test in `tests/`, **B** = firmware build, **HW** = bench/vehicle test owed by a human (see [VALIDATION.md](VALIDATION.md)).

### Measurement
- **REQ-M1:** The ADC's current source drives 250 µA out of A0, through Rref and the sender. Sender resistance is measured ratiometrically as `Rs = kReferenceOhms · Vs / Vref`, with Vref = A0−A1 and Vs = A1−A2. Both are measured at gain 1, PGA bypassed, against the internal reference, with the ADC's shorted-input offset subtracted from each. A ground offset inside the window does not enter `Rs`. *Evidence:* H (`temperature_test.cpp`: 120 Ω with 0 V and 0.15 V offset and with ±0.2 mV ADC offset, within 0.02 Ω); HW.
- **REQ-M2:** Each read cycle, every `kSampleIntervalMs` (250 ms), takes six single-shot conversions at 45 SPS:
  1. the offset (inputs shorted);
  2. Vref;
  3. Vs;
  4. A2 to ground with the 10 µA burn-out source on;
  5. A1 to ground with the burn-out source on;
  6. AVDD.

  Before each conversion, all four configuration registers are written and each is read back with its CRC; they must match what was written. Each result's CRC16 must match, and its conversion counter must follow the previous one. *Evidence:* H (`adc_frame_test.cpp`: CRC and frame decoding); B; HW.
- **REQ-M3:** Any I²C error, timeout, CRC failure, register mismatch or out-of-sequence counter yields `adc_ok = false`, never a stale value. The driver then resets the bus and retries on the next cycle, logging once per failure episode. *Evidence:* B; HW.

### Fault detection (never shows °C)
- **REQ-F1:** Faults are checked in this order, and the first match wins:
  1. ADC failure, non-finite values, or a shorted-input offset beyond `kAdcOffsetMaxV` (0.25 mV) → `NoAdc`;
  2. supply (AVDD) outside 2.9–3.5 V → `BadSupply`;
  3. ground offset (the A2 burn-out reading minus `kGroundSenseBiasV`) outside −0.10 to +0.20 V → `GroundFault`; this includes a broken sense wire or an open R2;
  4. the sender tap check (the A1 burn-out reading minus the A2 reading minus Vs) above `kSenderTapMaxV` (0.25 V) → `OpenCircuit`; this is an open R1;
  5. Vs ≤ 0 → `ShortCircuit`;
  6. Vref ≤ 0 or Rs > 5000 Ω → `OpenCircuit`;
  7. Rs < 20 Ω → `ShortCircuit`;
  8. excitation current Vref / `kReferenceOhms` outside 210–290 µA → `BadSupply`;
  9. no verified calibration → `NeedsCalibration`.

  *Evidence:* H (`temperature_test.cpp`).
- **REQ-F2:** A fault shorter than `kFaultResetMs` (3000 ms) keeps the filter and the latched alarm. A sustained fault resets both. *Evidence:* H (demo test, intermittent-connector block).

### Calibration
- **REQ-C1:** Fail closed. The repo default `kCalibrationVerified` is `false`, and uncalibrated firmware shows resistance in ohms, never °C. *Evidence:* H; B.
- **REQ-C2:** `main/CalibrationData.h` is produced only by `scripts/build_calibration.py` from human-measured points. The script rejects:
  - fewer than 5 points;
  - non-numeric or non-finite rows;
  - resistances ≤ 0;
  - non-monotonic data.

  *Evidence:* H (`test_calibration_tool.py`).
- **REQ-C3:** No extrapolation. Hotter than the table gives `AboveRange`, colder gives `BelowRange`, and neither shows a number. `BelowRange` is not a fault. *Evidence:* H (demo test).

### Temperature and alarms
- **REQ-T1:** Resistance is EMA-filtered (`kFilterAlpha` 0.2) before conversion. A reading below `kWarmThresholdC` (60 °C) is `Cold`. *Evidence:* H (partial).
- **REQ-T2:** Alarm targets are Amber at ≥ `kAmberThresholdC` (115 °C) and Red at ≥ `kRedThresholdC` (130 °C). `AboveRange` targets Red.
- **REQ-T3:** Escalation must be held for `kAlarmDebounceMs` (2500 ms), with separate Amber and Red timers. De-escalation is immediate but uses `kAlarmResetHysteresisC` (5 °C) of hysteresis, and Red steps down through Amber. **Exception:** while an alarm is latched, raw samples colder than the calibration table do not update the filter, the latched alarm or the maximum. The status is `BelowRange` and no temperature is shown. If such samples continue for `kBelowRangeHoldMs` (10 000 ms), the state resets as for a sustained fault (REQ-F2): alarm `Normal`, filter re-seeded. *Evidence:* H (partial; see CR-1 and CR-2 host tests).
- **REQ-T4:** The maximum temperature seen, and whether the table was ever exceeded, are tracked for display.
- **REQ-T5:** Millisecond timing uses `uint32_t` unsigned subtraction and must behave the same across counter wraparound. *Evidence:* none yet (see CR-1).

### Display and logging
- **REQ-D1:** The display offers twelve layouts: Classic, Sweep, Needle, Trace, Tape, OEM, White, Night, Nixie, Heritage, Track and Warm-up. The unit label, the status text, the bottom line, the demo banner and the colour rules apply to all twelve. The main reading (the digits) is in Classic, Sweep, Tape (in its window), Night, Nixie, Track and Warm-up; Needle, Trace, OEM, White and Heritage have no digital readout.
  - Unit label: with a verified calibration it shows `°C`, or `°F` when Fahrenheit is selected in menuconfig. Without one it shows `ohm` in every state. In Classic, Trace and Tape this is the title, `OIL °C`; in Sweep it is a small `°C` above `OIL TEMP`; in Needle it is under `OIL` at the bottom of the dial; in OEM it is under the 90 at 12 o'clock; in White it is under `OIL` below the hub; in Night it is the title, `OIL °C`, while lit, and a small `°C` under the dim reading while quiet; in Nixie it is the title, `OIL °C`, above the tubes; in Heritage it is under `OIL TEMP` below the pivot; in Track it is the title, `OIL °C`, at the top; in Warm-up it is the title, `OIL °C`, above the digits, as in Classic.
  - Main reading: it has no unit. It shows one of these:
    - the temperature in whole degrees of the selected unit, rounded half away from zero;
    - `>max` or `<min` beyond the table, with the limits converted to the selected unit;
    - the resistance in whole ohms when uncalibrated;
    - `--` on a fault.
  - Digit layout: fixed-width characters, right-aligned, so the ones digit never moves while the reading has up to three characters. In Classic, Warm-up, and Night while it's lit, the right three cells are centred on the screen (Nixie's four fixed tubes show the same four cells, so a 3-digit reading leaves the first tube dark), so a 3-digit reading is centred; a four-character reading (such as `>284`, or 4-digit ohms) uses all four cells, centred, and its ones digit sits half a cell further right. Sweep has three seven-segment cells, centred, with `<` or `>` drawn as a separate sign just left of them; a reading that needs four digits (a resistance of 1000 Ω or more, shown only when uncalibrated) is `--` in Sweep and shown in full in Classic.
  - Sweep dial: 40 segments over 30–130 °C (86–266 °F when °F is selected), with scale numbers every 20 °C (36 °F), so they read 30…130 (86…266). Each lit segment shows the graduated colour (below) of its own place on the scale, and unlit segments stay dim. The ghost digits behind Sweep's reading are fainter than the unlit segments, close to the background.
  - Sweep segments: they light only for a temperature inside the table. Beyond the top of the table they light up to the table's maximum. Below range, on a fault or when uncalibrated, none are lit. Scale numbers are hidden when uncalibrated.
  - LED (#10), on Sweep, Trace, OEM, White, Night, Nixie, Heritage and Track: a round light at 6 o'clock (on Sweep, in the ring's open bottom; on Trace, Nixie and Track, and on Night while it's lit, below the status lines; on White, in a round black socket below the hub, which shows a dark-grey lens while the LED is off; on Heritage, as a lamp in a chrome surround at the bottom, with a dark lens while off), in the reading's colour. On OEM the oil-temperature symbol below the hub is the LED, dark grey when it would be off. It pulses while an alarm is latched: slowly at Amber and faster at Red, starting and stopping with the alarm (its debounce and hysteresis). It's off on a fault and when uncalibrated, except while an alarm is still latched through a brief fault (under `kFaultResetMs`); then it keeps pulsing, as the digits keep the alarm colour. Below the table it stays lit, without pulsing unless an alarm is latched.
  - Needle (#11): a 270° white scale over Sweep's span (30–130 °C, or 86–266 °F), with five numbers (30, 55, 80, 105, 130 °C; 86, 131, 176, 221, 266 °F), a red needle and a hub, and no digital readout. The needle follows the Sweep segments' rules: hidden on a fault or when uncalibrated, at the start below the table, at the table maximum above it (capped at the scale's end), and clamped to the scale's ends. It eases towards each reading without overshooting and doesn't sweep when it appears. The scale numbers are hidden when uncalibrated.
  - Trace (#12): the last 60 s, one sample a second (the filtered value at the tick), newest on the right, as a thick line. Each point keeps the reading colour it was taken with, and that colour carries into the line around it, so the line shows the colours of the temperatures that made it. The newest point is a dot in its colour, or a ring when it's beyond the table, where the point sits at the table maximum. A fault or a reading below the table is a gap: no value is carried over or invented. The window is 30 °C tall, with ends on multiples of 5 °C. It stays put while the newest point is at least 3 °C inside it, and otherwise re-centres on that point. Grid lines every 10 °C, and amber and red lines at the alarm thresholds when they fall in the window. When uncalibrated there's no trace and no scale. The history is recorded whichever layout is showing, isn't saved across power cycles, and starts empty.
  - Shown in every layout (on OEM, in the wordmark's place whenever the wordmark isn't shown; on White, in the status window whenever it shows; on Night, whenever it's lit, which is whenever the wordmark isn't shown; on Heritage, in the legend's place whenever the legend isn't shown):
    - the status text;
    - the bottom line: the `MAX` value (whole degrees of the selected unit, no unit symbol) while calibrated with a reading in or beyond the table; otherwise `TEMPERATURE NOT VERIFIED` (uncalibrated) or `CHECK SENSOR AND WIRING` (fault);
    - in a demo build, `DEMO ONLY - NOT REAL`.
  - Background: pure black (`#000000`) on every layout, apart from White's white face, so the AMOLED's unused pixels are off. Tape's strip and window are black too. Drawn elements stay as designed: Classic's track, Sweep's unlit and ghost segments, Trace's grid, OEM's rim, Heritage's chrome bezel and lamp surround, the hubs and Tape's hatching.
  - Colour: the digits, the status text and Classic's arc take the graduated colour of the reading. The exception is Nixie's numerals, which are always nixie orange (#26); on Nixie the status text and the LED, both always shown, carry the colour. The bands are dark blue below 50 °C, light blue 50–69 °C, green 70–95 °C, yellow 96–105 °C, amber 106–119 °C and red from 120 °C, blending smoothly from one to the next (the same temperatures in °F). Beyond the table the colour is that of the table limit shown. The colour is never less severe than the latched alarm: an Amber alarm shows at least amber, and a Red alarm shows red. The alarm thresholds (REQ-T2) are unchanged, so red can show from 120 °C before the Red alarm at 130 °C. A fault, or any reading without a verified calibration, is amber (red while a Red alarm is latched). The colour rules are host-tested; how they look is checked on hardware.
  - Tape (#15): a 40 °C scale (72 °F) that scrolls past a fixed pointer. It has ticks every degree, numbers every 10, a strip in each temperature's graduated colour, and bars at the alarm thresholds. Beyond the calibration table it's hatched, with no numbers and no colour strip, and a marker shows the session maximum. The tape is centred on the reading: at the table maximum above the table, at the table minimum below it, and hidden on a fault or when uncalibrated. It eases to each reading without overshooting and doesn't scroll when it appears. The window shows the main reading, as Classic does. Under it, the rate of change is the least-squares slope of the newest 30 trace samples in °C/min (°F/min). It shows as an up or down arrow and the magnitude to 0.1, or `STEADY` below 0.5 °C/min. It's shown only when all 30 samples are present and inside the table. It's information only: no alarm or fault depends on it, and no future temperature is projected.
  - OEM (#17): styled on the Caterham factory gauges. A 270° scale over 50–130 °C in 8 steps of 10 °C (122–266 °F), a tick on each step and numbers at 70, 90, 110 and 130 °C (158, 194, 230, 266 °F), with 90 at 12 o'clock and no number at the start, as on the factory 0–8 bar gauge. An off-white needle with a counterweight and a hub, a greyscale face, and no digital readout. The needle follows Needle's rules on this span: hidden on a fault or when uncalibrated, at the start below the table, at the table maximum above it (capped at the scale's end), and clamped to the scale's ends; a reading in the table below 50 °C rests at the start. It eases towards each reading without overshooting and doesn't sweep when it appears. The scale numbers and unit are hidden when uncalibrated. The oil-temperature symbol is the LED (above). The word `CATERHAM` (plain text, not logo artwork) shows only with a verified calibration, outside the demo build, with the status `NORMAL` or `OIL WARMING`, a finite temperature and no alarm latched. Otherwise the status text, bottom line and demo banner show in its place.
  - White (#19): styled on a white-faced aftermarket oil-temperature gauge. A white face in a black ring, and a 270° scale over 40–140 °C with a tick every 2 °C (long at each 20 °C, medium at the other tens) and numbers at 40, 60, 80, 100, 120 and 140 °C (104, 140, 176, 212, 248, 284 °F), with 90 at 12 o'clock. A red needle with a counterweight and a hub, `OIL` and the unit below the hub, and no digital readout. The needle follows Needle's rules on this span: hidden on a fault or when uncalibrated, at the start below the table, at the table maximum above it (capped at the scale's end), and clamped to the scale's ends; a reading in the table below 40 °C rests at the start. It eases towards each reading without overshooting and doesn't sweep when it appears. The scale numbers and unit are hidden when uncalibrated. The LED (above) sits in a black socket below the legend. The status text, bottom line and demo banner are in a black window at the bottom of the dial, which shows whenever OEM's wordmark wouldn't: always in the demo build and when uncalibrated, and otherwise unless the status is `NORMAL` or `OIL WARMING` with a finite temperature and no alarm latched. The LED, the legend and the window sit in the bottom 90° that the needle never sweeps.
  - Night (#21): a dark layout on pure black, with no ring, face or ticks. It is quiet exactly when OEM's wordmark shows (a verified calibration, outside the demo build, the status `NORMAL` or `OIL WARMING`, a finite temperature and no alarm latched). Quiet, it shows only the main reading at the screen's centre in Montserrat 48, in its graduated colour at half brightness, the unit under it, dim, and a heartbeat dot under that. The dot's brightness steps once per display update, rising and falling between about 10 % and 40 % over 8 updates (2 s), and never repeats from one update to the next, so it stops if the updates stop. Otherwise it is lit: the main reading in Classic's digits at full brightness, centred, with the title above, the status text, bottom line and demo banner below, and the LED (above) under them. The demo build and the uncalibrated build are always lit. Quiet and lit switch at once, with no fade.
  - Nixie (#26): the main reading in four fixed nixie tubes, one per cell of Classic's right-aligned reading, so a tube with a blank cell stays dark. Each numeral (0–9, `-`, `<`, `>`) is drawn from line and elliptical-arc strokes as one connected wire, glowing nixie orange (a bright core over two dimmer, wider strokes), with the ten unlit numerals faint behind it, a faint mesh and a glass outline. Any character the tubes can't show makes the whole reading `--`, as in Classic. The title is above the tubes; the status text, bottom line, demo banner and the LED (above) are always shown below them. A tube is redrawn only when its character changes.

A reading counts towards Warming (`OIL WARMING`, and `BELOW CAL RANGE` when the table starts below 60 °C), Normal (`NORMAL`), High (`HIGH TEMPERATURE`) or Critical (`CRITICAL TEMP` and `ABOVE CAL RANGE`) only with a finite temperature (or beyond the table) and a verified calibration; anything else, every fault included, counts towards `--`. Each bar is its band's share of the total, in whole pixels adding up to the full bar, at least 2 px for any band with time in it. Times show as `m:ss`, then `1h05`, to `99h59`, then `99h+`.   - Warm-up (#27): a 270° ring like Classic's arc, open at the bottom, filled in the reading's colour from 0 °C at its start to the warm threshold (`kWarmThresholdC`, 60 °C) at its end, with the needle's rules: empty below the table, full above it, clamped to the ends, and **hidden altogether** (track and fill) on a fault or when uncalibrated, since an empty ring would read as cold oil. Classic's digits, the title above, and the status text, bottom line and demo banner below, then a warm-up line. Warm is the first reading with a verified calibration at or above the threshold (`NORMAL`, `HIGH TEMPERATURE` or `CRITICAL TEMP` with a finite temperature, or `ABOVE CAL RANGE`); the line then shows `WARM IN m:ss`, the time to that reading, kept for the power cycle even if the oil cools. If no cold reading (`OIL WARMING` with a finite temperature, or `BELOW CAL RANGE`) came before it, the line shows `WARM AT START`. Faults never count as warm or cold. The choice is stored (0 Classic, 1 Sweep, 2 Needle, 3 Trace, 4 Tape, 5 OEM, 6 White, 7 Night, 8 Nixie, 9 Heritage, 10 Track, 11 Warm-up) and restored at power-up; a missing or unknown value is Classic.

- **REQ-D2:** Once per second, a CSV line is logged with these columns: `uptime_ms,status,alarm,temp_c,resistance_ohms,ref_v,sender_v,supply_v,ground_offset_v`. *Evidence:* B; HW.
- **REQ-D3:** The read-only web log page (#32), built in only when menuconfig enables it and running only when the BOOT button selects it (REQ-D5), on the network of REQ-D4 (joined or hosted, from `main/wifi_secrets.h`). From power-up, whether Wi-Fi is on or not, the main loop appends one row a second, at the serial log's moment and with its values (REQ-D2), to a ring of the last 8 hours (28 800 rows) allocated once in PSRAM, numbered from 0 per session; and copies the gauge's status (its status and alarm, colour, maximum, Track's time per band and the warm-up text) at each sample. Both are under a short spinlock: the main loop never waits on the network. The server (`esp_http_server`, its own task at the lowest priority, at most 4 connections) answers only `GET /` (the page, built into the firmware), `GET /scale` (the thresholds, Sweep's segment colours and the reading colour every 2 °C) and `GET /log?since=N` (the status and up to 600 rows from row N; `since` must be a plain decimal number, otherwise 0); anything else is 404, and nothing on the page changes the gauge. Fail closed: every non-finite value is `null`, the temperature is `null` unless a verified calibration gave a finite one, and uncalibrated there is no maximum. The page (`docs/WEB_PAGE.md`) loads nothing from elsewhere; shows the gauge's own reading, colour and status (ohms and `CALIBRATION REQUIRED` uncalibrated; `DEMO ONLY - NOT REAL` in a demo build), never computing a temperature; turns its update age amber after 3 s and greys the reading to `--` after 10 s; charts the session with gaps where there was no temperature; keeps the session and the two before it in the browser's storage; and downloads a CSV of REQ-D2's columns plus `phone_time`, `session` and `sequence` (`DEMO-` in its name in a demo build). Failure to start (no PSRAM, the server, Wi-Fi) leaves the gauge working as without it. *Evidence:* H (`web_log_test.cpp`, `test_web_page.py`); B (with the page off and on); HW.
- **REQ-D4:** The UDP data stream (#33), built in only when menuconfig enables it and running only when the BOOT button selects it (REQ-D5). The network comes from `main/wifi_secrets.h` (git-ignored, never in the repo): an SSID of 1–32 characters and a WPA2 password of 8–63. Without it, Wi-Fi never starts. When started, the gauge scans for that SSID: if it's there, the gauge joins it as a client (WPA2 or better); if it isn't, the gauge hosts it as the access point with the same SSID and password (WPA2, at 192.168.4.1). A network that's there but can't be joined (within 15 s) is a failure, never hosted a second time. A joined network that drops is rejoined (10 s), and hosted once a scan no longer finds it. One version 1 packet per sample (`docs/UDP_STREAM.md`: 56 bytes, little-endian, magic `OILG`, session, sequence, uptime, frozen status and alarm codes, the REQ-D2 values and the session maximum as float32, CRC-32) goes to the multicast group and port from menuconfig (default `239.10.10.10:5005`) with TTL 1. Fail closed: the temperature is NaN and its flag clear unless a verified calibration and a finite temperature exist; every non-finite value is NaN; uncalibrated, there is no maximum. The stream is send-only, from a task below the main loop's priority with a non-blocking socket: the main loop only copies the newest sample into a one-slot mailbox, and a packet that can't be sent at once is dropped (its sequence number shows it). Failure to start leaves the gauge working as without Wi-Fi. *Evidence:* H (`udp_packet_test.cpp`, `test_udp_listen.py`, shared golden packets); B (with the stream off and on); HW.
- **REQ-D5:** The BOOT button (GPIO0, the top side button) controls Wi-Fi (#34). Each short press (debounced 30 ms, released within 1 s; longer presses and a button held since start-up don't count) moves to the next state, `Wifi Off` → `Wifi - Web On, UDP Off` → `Wifi - Web On, UDP On` → `Wifi - Web Off, UDP On` → `Wifi Off`, skipping states whose features aren't built in or when there are no usable settings. A panel on LVGL's top layer confirms it for 3 s after each press: the state, `Wifi starting...` and `Looking for <network>`, then `Joined <network>` or `Hosting <network>` with the gauge's address once up (shown again whenever that changes); `Wifi failed` in amber (back to off, not saved) if it can't start, with `Can't join <network>` when the network was there; `Wifi failed - no settings` or `Wifi not built` when it can't run at all. The panel sits in a band across the top of the screen that every layout keeps clear of its status lines, demo banner and LED (a `static_assert` in each), so it never hides an alarm, and the button changes nothing but Wi-Fi.
